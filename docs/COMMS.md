# Комунікаційний модуль (SMS / журнал дзвінків)

Версія: 1.0 · 2026-08-13 · **опційний, вимкнений за замовчуванням**

---

## 1. Що це і чого це не є

Модуль дозволяє адміністратору **явно зареєстрованого, авторизованого
власником** пристрою переглядати SMS та журнал дзвінків цього пристрою.

Дані беруться **виключно** із системних постачальників даних Android:

* `Telephony.Sms` — за рантайм-дозволом `READ_SMS`;
* `CallLog.Calls` — за рантайм-дозволом `READ_CALL_LOG`.

Це та сама інформація, яку бачать штатні застосунки «Повідомлення» й
«Телефон».

### Чого модуль НЕ робить (і не може легально)

| Заборонено | Чому неможливо |
|---|---|
| Перехоплення повідомлень чужих застосунків | Android не дає застосунку доступу до даних інших застосунків |
| Витягування OTP/кодів | немає окремого API; читається лише те, що вже в SMS-провайдері |
| Кейлогінг | застосунок не має доступу до введення в інших застосунках |
| Читання сповіщень задля вмісту | `NotificationListenerService` навмисно **не** використовується |
| Приховане стеження | стан модуля видно власнику на екрані агента |
| Обхід дозволів Android | немає — відсутній дозвіл означає «не збираємо» |

`RECEIVE_SMS` і `SEND_SMS` навмисно **не оголошені** в маніфесті:
перехоплення вхідних і надсилання від імені користувача модулю не потрібні.

Якщо якоїсь можливості немає через легальні API — вона позначається як
`unavailable`, а не обходиться.

## 2. Межі за замовчуванням

* **Вимкнено скрізь.** `CommsSettings.enabled = false` для кожного пристрою.
  Поки адміністратор явно не ввімкне модуль, агент нічого не читає й не
  надсилає.
* **Потрібне шифрування.** Без `COMMS_ENCRYPTION_KEY` модуль **неможливо
  ввімкнути** — сервер відповідає `409`. Це гарантує, що чутливі дані
  ніколи не ляжуть у БД відкритим текстом навіть за помилки конфігурації.
* **Два рубежі збору.** Агент збирає лише коли модуль увімкнено *і* дозвіл
  наданий. Сервер, приймаючи пакет, ще раз перевіряє, що модуль увімкнено
  (`409`, якщо ні) і що конкретний вид даних дозволено (інакше відхиляє).
* **Видимість власнику.** Коли модуль увімкнено, агент показує картку стану
  на головному екрані: що збирається, стан дозволів, режим «лише метадані».

## 3. Шифрування at rest

Тексти SMS, номери й контактні імена зберігаються в БД **лише
зашифрованими** — AES-256-GCM (`app/core/encryption.py`):

* ключ виводиться з `COMMS_ENCRYPTION_KEY` через HKDF-SHA256 (рівно 32 байти);
* кожен запис має власний випадковий 96-бітний nonce;
* `associated_data` прив'язує шифротекст до призначення (номер SMS не можна
  підставити замість номера дзвінка — розшифрування впаде);
* ключ живе **в оточенні**, а не в БД: маючи дамп бази, вміст не прочитати.

Відкритим текстом зберігається лише **довжина** тексту SMS — щоб панель
могла показати «(120 символів)» у режимі «лише метадані» без розшифрування.

У production `COMMS_ENCRYPTION_KEY` (якщо заданий) має бути ≥ 32 символів і
відрізнятися від інших секретів — інакше сервер не стартує.

## 4. RBAC

| Дозвіл | Хто | Що дає |
|---|---|---|
| `comms:manage` | admin, superadmin | вмикати/вимикати/налаштовувати модуль |
| `comms:read` | admin, superadmin | переглядати зібрані SMS/дзвінки |

Оператор і аудитор доступу до модуля **не мають** — ні до керування, ні до
вмісту. Це навмисно: перегляд особистих повідомлень тримається на
найвужчому колі.

---

## 5. Ретеншн

Кожен пристрій має власний строк зберігання (`retention_days`), обмежений
серверною стелею `COMMS_RETENTION_MAX_DAYS` (типово 90). Адміністратор може
задати менше, але не більше.

Фонова задача ретеншну (`comms_service.purge_expired`, той самий цикл, що й
для геолокації/аудиту) видаляє записи, старші за строк кожного пристрою.
Адміністратор може будь-коли видалити всі дані пристрою кнопкою (ендпоїнт
`POST /devices/{id}/comms/purge`).

Видалення пристрою каскадно прибирає його налаштування та зібрані дані.

## 6. Аудит

| Подія | Коли |
|---|---|
| `COMMS_ENABLED` | модуль увімкнено (з точним часом і хто) |
| `COMMS_DISABLED` | модуль вимкнено |
| `COMMS_CONFIG_CHANGED` | будь-яка зміна конфігурації (before/after) |
| `COMMS_PERMISSION_CHANGED` | агент повідомив новий стан дозволів |
| `COMMS_DATA_INGESTED` | прийнято пакет (лише кількості, без вмісту) |
| `COMMS_DATA_VIEWED` | **адміністратор переглянув** SMS чи дзвінки |
| `COMMS_DATA_PURGED` | дані видалено |

`COMMS_DATA_VIEWED` — ключова подія приватності: доступ до чутливого вмісту
ніколи не буває «тихим». Самі тексти в аудит **не потрапляють** — лише факт
і кількість переглянутого.

Точний час увімкнення зберігається в `CommsSettings.enabled_at` і
повертається в API (`enabled_at`, `enabled_by_email`).

## 7. API

Адміністративні (`/devices/{id}/comms`):

| Метод | Шлях | Дозвіл |
|---|---|---|
| GET | `` | `comms:manage` — стан модуля |
| PUT | `` | `comms:manage` — увімкнути/вимкнути/налаштувати |
| POST | `/purge` | `comms:manage` — видалити зібране |
| GET | `/messages` | `comms:read` — розшифровані SMS (з аудитом) |
| GET | `/calls` | `comms:read` — розшифрований журнал дзвінків (з аудитом) |

Агентські (device-JWT):

| Метод | Шлях | Опис |
|---|---|---|
| GET | `/device/comms/config` | що збирати (`enabled=false` = нічого) |
| POST | `/device/comms/permissions` | агент повідомляє стан READ_SMS/READ_CALL_LOG |
| POST | `/device/comms/data` | пакет SMS/дзвінків (лише коли модуль увімкнено) |

Команди реєстру: `COMMS_SYNC` (перечитати конфіг і стан дозволів),
`COMMS_COLLECT` (позачерговий збір) — обидві потребують `comms:manage`.

## 8. Агент (Android)

* **Джерела** — лише `Telephony.Sms` і `CallLog.Calls` через `ContentResolver`
  (`comms/CommsCollector.kt`). Жодних notification listener, accessibility
  scraping чи root тут немає.
* **Дозволи** — `READ_SMS`, `READ_CALL_LOG` оголошені в маніфесті, але
  **запитуються лише** коли адміністратор увімкнув модуль, кнопкою «Надати
  дозвіл» на екрані агента. Користувач може відмовити.
* **Стан дозволів** повідомляється серверу навіть при вимкненому зборі —
  панель бачить реальну картину, а не здогадку.
* **Режим «лише метадані»** (`metadata_only`) — агент не читає текст SMS
  взагалі, лише номер, напрямок і час.
* **Видимість** — картка «Повідомлення та дзвінки» на головному екрані
  агента, поки модуль увімкнено.

---

## 9. Обмеження цієї версії

- MMS не збираються (лише SMS).
- Вміст дзвінків не записується — Android такого API застосунку не надає
  (і ми його не імітуємо).
- Пошук/фільтр за номером у панелі поки немає — лише хронологічний перелік.
- Дедуплікація — за `provider_id` рядка content provider'а; після скидання
  провайдера на пристрої ті самі записи можуть надійти як нові.
